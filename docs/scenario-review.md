# 真实审阅场景检查

检查日期：2026-11-05。基于当前 0.1.0 源码和 `verification.md` 中的验证记录。
这是行为审查及后续需求建议，不表示下列能力已经实现，也不将静态风险表述为实测故障。

## 建议的行为约定

插件应维护有明确起止边界的审阅会话。会话内，代码跳转可以经过普通源码、原生候选弹窗和用法列表；目标属于审阅范围且可显示 Diff 时，回到对应暂存区 Diff。无修改文件仍使用普通源码。离开会话后恢复日常导航。

会话不应接管所有普通文件打开操作。项目树、搜索文件、手动选择其他编辑器是否继续会话，需要明确区分；关闭所属预览、结束审阅或关闭项目应结束会话。跨普通文件的代码导航不应自动结束会话。原生候选选择、分屏意图和不抢焦点的要求应得到保留。

## 第一优先级：使基本流程完整

| 场景 | 当前证据及影响 | 建议行为 |
| --- | --- | --- |
| Diff → 未修改枚举 → 用法结果 → 修改文件 | `StageNavigationHandler` 要求当前上下文含 Diff；`processor()` 要求编辑器隶属暂存区预览。普通文件后无法继续接管。用法结果各入口仍需实测。 | 会话跨普通源码和用法结果保留；最终落点进入适合的 Diff；解析及多目标选择仍由 GoLand 完成。 |
| 混合路径前进／后退 | `canTravel()` 只接受原暂存区处理器；普通源码不参与插件历史。 | `A Diff → B 源码 → C Diff` 连续后退恢复 B、A，前进反向恢复；后退后新导航正确截断前进分支。 |
| Review 中暂存、取消暂存或编辑 | `travel()` 要求原路径和原暂存分组仍存在；找不到时清空历史。内容指纹变化导致历史跳转 fallback 时也清空历史。 | 在比较版本变化后重新确认目标位置；能够映射则恢复，不能映射则降级或跳过该节点并解释原因，保留其他有效历史。不得静默使用旧偏移。 |
| 导航加载期间目标被编辑 | `finish()` 在内容指纹变化时降级，但新导航的 `fallback()` 仍以最初保存的整数偏移打开源码。旧坐标在源码回退路径仍可能指向错误位置。 | 回退保留并验证有效位置标记，或重新解析目标；无法确认时只打开文件，不声称定位成功。 |
| 同一文件部分暂存 | `findTarget()` 固定优先未暂存；INDEX 与本地不同的声明解析没有插件补充。已有测试只证明不同内容的历史恢复，不能证明这种情况下的原生声明解析可用。 | 明确选择“跟随导航目标版本”或“固定审阅范围”。若固定只审已暂存，目标不存在于 INDEX 时说明并打开源码，不伪造 INDEX 坐标。版本映射只在能确认目标身份时使用。 |
| 进入、暂停、结束审阅 | 目前只有 Diff 右键临时开关；项目内存布尔值重启恢复开启；无 Settings 页面、可见会话状态。 | 提供设置入口、持久化启用偏好和可见状态；支持暂停／结束及单次以源码打开。持久化偏好，不自动恢复失效会话。 |

## 第二优先级：稳定性和可解释性

| 场景 | 当前证据及影响 | 建议行为与验证 |
| --- | --- | --- |
| 连续快速跳转、加载较慢 | 有 pending 时新的请求直接交回原生；5 秒后可能降级源码。实际焦点竞争尚未实测。 | 后一次明确导航意图应取消前一次；用户切换目标后不得被迟到结果拉回。取消、超时、关闭预览分别测试。 |
| 同项目多个窗口／预览、右侧分屏 | 项目服务只有一个 session/history；切换处理器会清空历史。右侧分屏明确交回原生。项目级标签选择监听没有限定原始分屏；其他分屏切换是否误取消当前加载，待实测。 | 审阅状态和取消条件按所属预览／窗口隔离；保留显式分屏意图，避免错误复用另一窗口预览。 |
| 文件改名、删除、冲突、二进制、外部库 | 当前以路径查找目标，支持双栏文本及有限暂存分组。其余路径不具备通用支持。 | 无可用文本 Diff 时保留原生行为；改名后尽可能追踪身份。不能跳转时不破坏会话或整条历史。 |
| 用户不知道为何没进入 Diff | 多处条件直接返回原生，无面向用户的原因说明。 | 提供按需的“最近一次导航原因”：无修改、不在范围、版本不匹配、不支持视图、超时。避免每次弹通知，诊断不采集源码。 |
| 大文件、高频跳转 | 整份文档转 UTF-8 并计算 SHA-256，调用处位于 EDT；存在分配和延迟风险，尚未测量。 | 用大文件测延迟及界面响应，再决定缓存／后台计算方案；改进不能削弱版本一致性校验。 |

## 配置建议

首轮只增加少量配置：插件启用、是否从暂存区 Diff 自动开始会话、目标比较范围策略。另提供开始／暂停／结束审阅、单次普通源码打开和诊断动作。

比较范围的初始默认值建议维持“跟随导航目标版本”：原生解析通常给出本地文件坐标，应优先在本地侧展示。固定只审已暂存属于显式模式，不能直接将本地行号套到 INDEX。界面始终标明 HEAD ↔ INDEX 或 INDEX ↔ 本地，避免无感切换基线。

## 后续范围

在上述流程通过后，再考虑 Unified、Combined。历史提交、PR 评论、批量暂存、自动执行 Git 操作暂不扩展；它们会引入新的版本及写入语义，不能解决当前导航链路缺口。

## 验收矩阵

1. 真实 Ctrl+Click、Ctrl+B，以及查找用法结果双击／回车，均验证最终文件、版本、侧别和符号位置。
2. Diff → 未修改源码 → 修改文件，Back／Forward 连续恢复混合路径，已有源码标签保留。
3. 同一文件同时存在已暂存和未暂存修改；目标符号仅存在于某一版本或在两个版本有不同行号。
4. 返回前暂存／取消暂存、编辑导致行号变化、改名或删除目标；有效历史不整体丢失，失效位置不误定位。
5. 连续触发两次导航、加载中切换标签／树选中项、关闭预览和超时；最终状态服从最后有效意图。
6. 同项目多窗口、多个 Git root、显式右侧分屏；不串会话，不抢其他窗口焦点。
7. 索引中、未跟踪文件、冲突、二进制及外部依赖；合理降级，并能按需解释原因。
8. 暂停／结束后普通导航恢复；重启保留偏好但不恢复过期会话。

现有 17 项集成断言不能替代以上矩阵，尤其不能据此宣称真实用法弹窗和混合历史已经通过验证。
