# Git Diff Review

增强 JetBrains IDE 的 Git 暂存区审阅：在 Diff 中跟随代码跳转、按选中行暂存，并让提交面板跟随活动文件。

项目地址：[youjiaxing/git-diff-review](https://github.com/youjiaxing/git-diff-review)。当前完成实际验证的是 GoLand 2026.2（平台 build 262）；其他 JetBrains IDE 尚未完成兼容性验证。

## 行为

- 从暂存区 Diff 开始审阅会话；经过未修改源码后，继续跳转到修改文件仍回到 Diff。
- 保留原生声明解析及多目标选择；单个查找用法结果的 EditSource／回车及结果树双击可以延续已有会话。
- 主动跳转到目标 Diff 后，光标精确定位到方法名或符号，水平视口回到第一列，完整显示声明前缀；双栏两侧同步归零，新增文件单栏同样适用。审阅 Back／Forward 使用相同定位规则；跳转完成后的手动水平滚动不会被延迟回调覆盖。
- 默认 **只审未暂存修改**：有未暂存修改时进入 INDEX ↔ 本地，未跟踪新文件进入原生单栏 Diff；只有已暂存修改或没有修改时打开普通源码，保留审阅会话。需要回看已审内容时，可手动打开已暂存 Diff，或主动设置为只审已暂存。
- 复用当前提交预览、同步提交树选中项，保留 IDE 原生的暂存、取消暂存、还原控件。
- 普通源码菜单 **与暂存版本比较** 优先进入同一编辑窗口的提交审阅预览，精确显示当前文件的 INDEX ↔ 本地，支持 **Stage 选中行**。纯未跟踪新文件也可使用此菜单，先显示原生“空版本 ↔ 本地”单栏 Diff，打开预览不会创建暂存条目。显式比较会显示隐藏的提交面板、替换树选区，并保留源码标签；不受自动导航的已暂存范围或新增文件偏好影响，也不重置暂停／自动开始设置。没有对应未暂存项、插件禁用或目标不支持时保留原生比较；纯新文件无法打开预览时保留／恢复原源码并记录原因。其他比较菜单不接管。
- 通过现有 Back / Forward 键位恢复源码与 Diff 混合路径，包括侧别和光标；内容变化不会清空整条历史。默认模式返回时按当前未暂存状态重算：全部暂存后打开源码，取消暂存后可恢复未暂存 Diff；显式单次打开源码和新增文件偏好关闭所选择的源码仍按原意图恢复。
- 无修改文件使用普通源码；未参加会话的普通导航、冲突视图、显式分屏及不支持的视图保留原生行为。
- 源码标签不会被自动关闭；显式点击 Stage／Unstage 选中行才写入 Git 暂存区，Discard 选中修改只改本地编辑器文档，不执行 commit。
- 状态栏 **Diff Review: On / Idle / Off** 显示会话状态；点击可暂停审阅、查看最近导航原因或打开设置。
- Diff／源码右键 **Start / Pause Diff Review** 控制会话；Diff 右键 **Open Review File as Source** 单次打开源码并保留返回路径。
- **设置 → 版本控制 → Git Diff Review**：持久化项目启用偏好、自动开始和目标比较范围。应用设置会结束当前会话并清空审阅历史，下次从 Diff 开始；会话及历史不跨重启恢复。
- **跳转到新增文件时使用 Diff** 默认开启。默认范围下未跟踪、部分暂存的新文件可以进入未暂存 Diff，全部暂存的新文件打开源码；主动选择「只审已暂存」时则按 INDEX 范围处理。关闭后，导航到新增文件会打开普通源码并保留审阅路径；手动打开新增文件 Diff 仍可开始或继续审阅。旧配置缺少此项时默认开启，已保存的关闭值会保留。
- 手动切到无关源码后不继续接管；关闭所属 Diff 预览会释放会话。

## 按行暂存与取消暂存

普通源码也支持按连续选区 Stage／Unstage：编辑器顶部显示选区状态和有效操作，右键菜单及原有选行动作同样可用。Stage 要求源码已保存，插件不主动保存。取消暂存仅在源码选区可唯一映射到 INDEX 时直接执行；暂存后再次修改、重复文本无法确认对应关系或已暂存删除没有可选 INDEX 行时，提供“在 Diff 中选择取消暂存”，打开 HEAD ↔ INDEX 后重新选行，打开本身不写入。正常操作保留源码、选区和阅读位置。

普通源码采用与 GoLand 原生一致的标记：**实心＝未暂存、空心＝已暂存、半填充＝已暂存且另有修改**；颜色仍表示新增、修改和删除类型。状态分别依据 HEAD→INDEX 和 INDEX→源码的行差异计算：整份新文件暂存后只修改一行，仅该行显示半填充，其余仍为已暂存空心；删除用独立行间三角标记，不把相邻源码行改成混合状态。每段同状态区域首行末尾增加文字注释，不写入代码；悬停说明实际行或行间删除的状态。折叠区域按原生可见范围合并显示。点击有未暂存变化的标记，使用原生代码弹窗显示该真实修改块的“暂存版本 ↔ 本地”及上下文，直接暂存该块，或取消对应 INDEX 行的暂存；多行替换和删除点同样显示真实前后代码，不跳转另一种 Diff。操作范围以弹窗标注的修改行为准，保留源码选区和光标；没有后续本地修改的位置及不支持情况保留原生弹窗。点击沿用原生标记命中带，并消费已接管的鼠标事件，避免随后触发断点切换；正常断点区域仍由 IDE 处理。此样式仅用于普通源码，Diff 内保留原生比较高亮。设置中可关闭“普通源码显示暂存状态并支持选行操作”，关闭或卸载时恢复原始标记。

标记绘制适配限定平台 262；无法唯一识别原生标记时保留原生样式，顶部说明回退。源码选行暂存复用既有 INDEX 锁、版本校验和事务互斥，冲突、重命名等不支持类型保留原生操作。

在暂存区文本 Diff 中鼠标选中单行或连续多行，附近会出现当前选区有效的 **Stage 选中行**／**Unstage 选中行**／**Discard 选中修改**；也可使用 Diff 右键菜单，并在 Keymap 为动作绑定快捷键。可用操作在后台核实后显示，不固定按屏幕左右判断。INDEX ↔ 本地左侧的已暂存内容通过 HEAD ↔ INDEX 判断 Unstage；尚未暂存的删除仍可 Stage 或 Discard。右侧本地选区提供 Stage／Discard，不猜测跨版本 Unstage。原合并快捷动作只有一种有效操作时直接执行，Stage／Unstage 都有效时明确选择，绝不会隐式执行 Discard。

浮窗靠近实际选取终点，向上和向下拖选使用同一规则；空间不足时自动翻到上方或向内避让，完整保留在所属侧代码区域。终点滚出视口后，选区仍有效时按钮贴边保留；滚动和调整分栏会重新定位，窄侧自动竖排、分行，全部有效操作仍可到达。Stage 使用主题强调样式，浮窗有独立底色、边框和阴影，不将 Enter 绑定成默认暂存。

明确的修改直接执行。调用修改与后续新增内容被合成替换块时，会依据明确对应的修改行及紧邻的不变行尝试重新拆分，让独立新增内容保留原本位置。无法定位的局部不等长替换不生成写入候选，提示扩大选区覆盖完整替换块；等长局部替换仍提供只读确认预览，取消不修改。选中完整原生修改块保持既有含义；不会自动扩大选区。没有选区、只选未修改内容或多个不连续选区不会写入，也不会扩大为整个区块。

Discard 以 INDEX 为基线，仅撤销选中的未暂存修改，直接更新真实本地文档，保留暂存内容、未选修改和其他未保存编辑。每次操作对应独立 IDE 撤销命令，支持 Undo／Redo；不主动保存文件，后续 Stage 仍要求先保存。纯未跟踪文件使用空基线，清空内容后保留空文件。Discard 仅支持现存普通文本文件的双栏及右侧单栏视图，不包含恢复整份已删除文件；原有删除侧单栏 Stage／Unstage 保留。

新增文件部分 Stage 后，当前预览自动从整份新增的单栏视图切换为 INDEX ↔ 本地，继续显示剩余未暂存修改；连续 Stage 也会重新加载最新基线。新预览布局可用时同步保持操作内容的位置，避免先显示顶部再滚回；定位以整个预览区域为参照，保留标题高度变化及顶部部分裁切的像素偏移，不按旧光标强制居中。选区超过一屏时保留原来可见的部分。写入及刷新期间禁止再次使用旧视图选行操作，确认预览中的 INDEX 及恢复位置已稳定后恢复。用户滚动、点击定位、切换文件、导航、手动选树或关闭预览会取消迟到的位置恢复与自动重选，切走再切回也不会恢复旧请求；已经成功的暂存写入保留，Git 状态仍可后台更新。无法确认刷新结果时保留写入结果并记录原因，可从提交面板重新打开，不额外暂存或跳到其他文件。

内容变化导致的过期操作会取消，异步失败原因记录在状态栏提示及 **Diff Review Navigation Reason** 中，不再弹出需要点击 OK 的模态信息框。未保存源码等执行前提示，以及确需确认的歧义暂存预览仍保留。

仅更新对应文件的暂存内容，保留工作区及无关已暂存修改。写入采用 Git index 锁，在锁内校验基线并原子发布；文件、HEAD、INDEX 或文档在最终校验前变化时取消，不强制覆盖。不承诺跨 HEAD、工作区及 INDEX 的联合事务，最终校验后的源文件变化作为后续修改显示。

保留已有文件的编码、BOM 与未选行的原始换行格式；新增文件完整 Unstage 后移除 INDEX 条目、本地文件保留；工作区清空文件与删除文件分别保留空条目或移除条目。仅编辑候选后无法确认混合换行重复行的身份时拒绝写入。

Stage 前本地编辑需已保存，未保存时不提供可执行 Stage，插件不自动保存源码。冲突、重命名、符号链接、子模块、二进制和纯元数据变更使用原生操作；大文件或无法安全处理的候选会说明原因。改选、切换预览或版本变化使旧候选失效；操作不会在切走后重新发起。插件自身跨预览的选行写入按 INDEX 路径互斥，Discard 在后台只读复核 Git 基线，在 IDE 写命令内复核文档，不承诺与外部 Git／文件写入的联合事务。

## 标签定位提交面板

提交面板已显示时，默认切换源码标签只选中并滚动到对应的未暂存／未跟踪项；即使同文件此前选在已暂存，也会改选未暂存，没有对应项则保留原选区。手动查看的 Diff 按其实际比较分组定位；主动选择「只审已暂存」时，普通源码跟随保留原有分组行为。单选目录不算多选，即使目录内含目标文件，也会精确选中该文件。实际选中多个树节点或后续手动选树优先，过期的异步定位不能覆盖手动选择。此功能独立于新增文件的 Diff 偏好开关。

被动标签定位不打开隐藏面板、不改变过滤、不切换源码到 Diff、不抢焦点；文件不在当前树中时保留原选区。此定位独立于审阅会话，不执行 Git 写入。原生后台预览可能随树更新，显式返回已有审阅预览时会恢复原文件、原分组与可确认位置，包括手动打开的已暂存 Diff；原分组消失时尝试当前范围内的 Diff，否则返回原文件源码。该预览恢复与默认 Back／Forward 的未暂存规则分开处理。

0.3.3 保留既有配置中的 `FOLLOW_TARGET` 标识，将其行为及显示名更新为「只审未暂存修改」；已有项目同样采用新规则，其他偏好及主动保存的「只审已暂存」保持不变。

## 兼容范围

首版适配 **GoLand 2026.2，build 262**，开发 SDK 为 **2026.2.2.1 / GO-262.10315.160**，需要 JDK 25 构建。

目前接管提交工具窗口的**双栏 Git Staging Diff**，以及新增文件的**原生单栏文本 Diff**，支持单双栏互跳和混合历史。仅删除侧的单栏、Unified、Combined、三栏、历史提交及普通单文件比较使用原生导航。内部 API 有版本约束，因此插件将兼容版本限定在 `262.*`。

INDEX 文件与工作区内容相同时，声明解析会使用工作区 PSI 上下文。内容不同时保留原生解析，仍不保证 INDEX 中的声明解析能成功。目标定位使用可跟随编辑的位置标记；跨文档仅接受来源、目标均无歧义的上下文或符号整行匹配，不能确认时打开源码而不使用旧偏移。固定只审已暂存时，目标没有可用 INDEX 或无法确认对应位置，也使用源码。

同项目会话按预览保存历史；多窗口／分屏交互尚未完整验证。用法适配目前限单个 `UsageInfo2UsageAdapter` 结果和结果树，批量打开及其他用法弹窗路径保留原生行为。

## 本地构建

无需网络下载构建依赖，直接使用已安装的 GoLand SDK：

```powershell
.\scripts\build-local.ps1 `
  -IdePath 'C:\path\to\GoLand' `
  -JdkPath 'C:\path\to\jdk-25'
```

输出 `build/local/git-diff-review-<版本号>.zip`。唯一版本来源为 `gradle.properties` 的 `pluginVersion`，本地打包、安装和 Gradle 描述符都读取该值。脚本会先运行历史、选中行变换及独立临时 Git 仓库的事务检查。

源码标记和局部暂存的定向回归使用跨平台 Node.js 入口编排现有 GoLand 测试阶段；它会为每个阶段隔离测试配置，汇总 smoke 报告和平台错误，失败时保留对应沙箱：

```text
node scripts/run-source-marker-regression.mjs --ide-path "C:\path\to\GoLand" --jdk-path "C:\path\to\jdk-25" --test-config-path "C:\path\to\licensed-test-config"
```

入口支持 `--skip-full`、`--plugin-archive`、`--dry-run` 和 `--timeout-ms`；具体参数以 `node scripts/run-source-marker-regression.mjs --help` 为准。Node.js 是用户入口，GoLand 适配器由 `DIFFNAV_PWSH` 指定或自动选择 `pwsh`。

本地更新使用 `scripts/install-local.ps1`（同样传入 `-IdePath`／`-JdkPath`）。默认先校验并准备安装包，后台等待同一 GoLand 安装的进程完全退出、旧插件 JAR 的文件锁释放，然后备份旧目录、离线替换、核对唯一版本及摘要，成功后自动重新打开 GoLand。**保存并正常退出后不要手动重开，等待助手完成更新。** 助手不会关闭 IDE；失败会恢复旧目录，恢复被锁阻塞时记录 `recovery_pending` 并等待释放。状态文件路径会输出到终端，备份保存在 IDE 配置目录的 `diffnav-update` 下。

`-VerifyOnly` 在隔离目录验证实际文件锁、目录提升失败回滚、恢复自身受阻及无关启动任务保留；`-UseStartupQueue` 显式选择原来的启动队列方式。启动队列执行失败后 IDE 可能清掉任务，不会自动重试，不能把“已排队”视为实际安装成功。

标准 Gradle 构建使用 [IntelliJ Platform Gradle Plugin](https://plugins.jetbrains.com/docs/intellij/tools-intellij-platform-gradle-plugin.html)：

```powershell
# JAVA_HOME 指向 JDK 25
.\gradlew.bat buildPlugin -PlocalIdePath='C:\path\to\GoLand'
# 省略 localIdePath 时下载 gradle.properties 指定的 SDK
```

Gradle 输出在 `build/distributions/`。首次运行需要访问 Gradle、JetBrains 和 Maven 仓库；本地 SDK 脚本可用于这些服务不可访问时。

## 验证

`src/test` 包含无需第三方依赖的历史回归检查，覆盖连续跳转、停留位置、后退后分叉、失败不移动游标以及容量上限。

`src/smoke` 是单独打包的 IDE 集成测试插件，**不包含在正式安装包内**：

```powershell
.\scripts\start-sandbox.ps1 -IdePath 'C:\path\to\GoLand' -JdkPath 'C:\path\to\jdk-25'
```

它会在 `build/sandbox/` 下创建测试 Git 仓库、独立 IDE 配置和测试插件，打开另一个 GoLand 实例，运行原生声明跳转与审阅历史检查。报告位于 `build/sandbox/smoke-report.txt`。关闭该测试实例后，可用 `-Reuse` 重跑；不会复制主 IDE 的配置或账户数据。

## 安装与卸载

正式安装包下载入口：[GitHub Releases](https://github.com/youjiaxing/git-diff-review/releases)。选择对应版本的 `git-diff-review-<版本号>.zip`，不要选择 GitHub 自动生成的 Source code 压缩包。可用同名 `.sha256` 文件核对安装包摘要；`release-manifest.json` 记录构建提交、工作流运行及原始安装包身份。

GoLand → 设置 → 插件 → 齿轮 → 从磁盘安装插件，选择生成的 ZIP，并按 IDE 提示重启。随后在「提交」工具窗口的未暂存文件上打开 Diff，即可使用原有代码跳转操作。

本机已安装旧版时，也可运行 `scripts/install-local.ps1 -IdePath ... -JdkPath ...`：先准备校验过的新版，等待当前 GoLand 正常退出且旧 JAR 文件锁释放后离线替换，成功后自动重开，不强制结束 IDE。**退出后不要手动重开，等待助手完成。** `-VerifyOnly` 在 `build/` 隔离目录验证文件锁、失败恢复和无关队列保留，不修改日常安装。

0.3.1 起插件名称为 **Git Diff Review**，ID 为 `io.github.youjiaxing.git-diff-review`，目录及安装包统一为 `git-diff-review`。旧名称为 GoLand Diff Navigation，旧 ID 为 `io.github.youjiaxing.goland-diff-navigation`。这是一次有意的重新安装，旧 ID 不作为升级身份保留。

使用安装脚本时，退出后会将旧、新两个安装目录整体备份到插件扫描目录之外，再只安装新 ID；只清理本插件遗留的待安装任务，保留其他插件的队列任务。若手动安装 ZIP，请先卸载旧 ID 的插件，避免同时启用两份。项目偏好以新组件名保存，旧偏好不会自动迁移；Git 仓库与审阅中的源码不受影响。

安装脚本默认从指定 IDE 的 `product-info.json` 推导配置和系统目录；自定义位置可显式传入 `-ConfigPath` 和 `-SystemPath`。测试启动脚本仍以 GoLand 为验证环境。

卸载：设置 → 插件 → Git Diff Review → 卸载。审阅历史仅保存在内存中。

## 提交、构建与自动发布

授权提交并推送插件更新时，同时授权该版本的 GitHub Release 公开发布，无需另行打标签或再次确认发布。提交前维护正式 `major.minor.patch` 版本，常规修复递增 patch；用户指定版本优先。插件源码、构建、打包及验证流程修改都要求更新版本。仅 Markdown／docs 等文档修改不重复发版，流水线不会自动提交版本号。

`main` 推送自动执行 Windows／Java 25 远端 SDK 构建、历史／选区变换／真实 Git 事务检查及最终 ZIP 核验；通过后创建指向实际构建提交的 `v<版本号>` 标签和正式 Release，发布安装 ZIP、校验文件及构建证据。PR 和其他分支不发布。CI 不自动运行本机全部 IDE 集成或鼠标体验检查，当前实测兼容范围仍为 GoLand 262。

发布以目标提交历史中最近成功的本流程正式版本为基线，累计检查尚未发布的源码、构建和验证变更；失败后补推文档也不能掩盖漏改版本号。相同版本的产物变更会失败，不覆盖旧标签或公开安装包。同一发行重跑核验已有原始资产；未完成草稿只恢复能确认原始构建身份的内容。不同版本可以并行完成，Latest 单独串行重算最高正式版本。

首次接入时 `.github/release-policy.json` 的 `automatic` 保持 `false`：先取得成功的远端构建产物，在隔离 GoLand 验证该确切 ZIP 的加载，再通过同一工作流的手动入口指定 `publish=true`、原 `source_run_id` 和已验证的 `expected_sha256` 完成首次公开。CLI 没有手动触发权限时，也可提交 `docs/release-bootstrap.json` 的隔离验证记录（仓库、版本、完整提交 SHA、原 run／artifact ID 和安装 ZIP SHA-256），并开放门禁，由 main push 复核并发布记录中的确切产物。该入口只处理尚未公开的对应版本；版本发布后记录失效，不能重新发行或覆盖资产。

仅切换已经验证的自动发布门禁为 `true` 的配置提交可沿用原版本；此例外不包含构建、校验或资产选择逻辑修改。门禁开放后正常推送无需再操作首次验证入口。需要恢复 Latest 时可手动运行工作流或重跑对应 Latest job。

若首次发行已经创建草稿、但发布工具需要修复，可用 `docs/release-recovery.json` 记录原版本、提交、run／artifact ID 和摘要。独立恢复任务只认领已经存在、归属本流程且标签和原始 manifest 均匹配的草稿，下载原构建的确切字节后继续上传；不创建其他版本、不移动标签。该记录在版本公开后只核验原资产，不再依赖过期的 Actions artifact。发布工具本身的修复仍按普通版本规则递增当前版本，由正常流程构建发布。

## 实现入口

- `StageNavigationHandler`：在原生导航最终打开源码之前接收 `SourceNavigationRequest`。
- `StageNavigationService`：选择暂存区目标、同步预览、加载后定位、取消失效操作。
- `IndexDeclarationHandler`：为内容相同的 INDEX 快照补充工作区解析上下文。
- `ReviewHistory`：保存同一预览内的文件、分组、侧别、位置及前进／后退路径。
- `ReviewHistoryAction` / `ReviewActionListener`：沿用键位并接入可用的原生导航按钮。
- `SourceCompareService`：将显式源码比较交给提交预览，管理初始化、目标校验、过期取消和原生回退。
- `CompareWithStagedAction`：扩展纯新增源码的比较菜单启用条件，委托原生动作；声明式覆盖由平台负责卸载恢复。
- `StageRefreshService`：按当前用户意图，在写入后等待新树节点并重新加载、核对暂存基线。

源码和构建产物不包含业务项目代码、IDE 二进制或账户凭据。
